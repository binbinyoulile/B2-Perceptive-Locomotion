# Go2 台阶任务分层混合架构规划

> 文档状态：设计方案，尚未实现。  
> 更新时间：2026-10-28。  
> 当前约束：暂停纯端到端 RL 长训；本阶段只整理代码与实验产物、沉淀复盘结论，不新增控制功能，不启动训练。

## 1. 目标与边界

### 1.1 项目目标

让 Unitree Go2 在 MuJoCo 中稳定完成低台阶跨越，并保留迁移到真实机器人和后续多级楼梯的工程接口。首要目标不是追求某个随机种子下的最高成功率，而是建立一个：

1. 行为可解释；
2. 失败可定位；
3. 可重复评测；
4. 有安全回退；
5. 能逐步扩展到多级台阶的基线。

### 1.2 本阶段不做的事

- 不实现新的 FSM、控制器或训练脚本；
- 不恢复任何已归档训练入口；
- 不启动 PPO 或其他训练；
- 不承诺当前 163 维环境已经能完成台阶跨越；
- 不把历史 checkpoint 当作新架构的默认起点。

### 1.3 为什么放弃纯端到端 RL

历史实验表明，纯端到端 PPO 的主要问题不是训练步数不足，而是行为链太长、成功信号太稀疏、奖励之间互相冲突。策略反复落入以下局部最优：

- 为获得抬脚奖励而全腾空；
- 为获得存活奖励而原地踏步或站立；
- 抬起前腿但不把机身重心送过台阶前缘；
- 前足搭台后，后足持续在台前蹭地；
- 通过缩短出生距离、降低台阶高度等脚手架获得不可外推的高成功率；
- 在“动作饱和”和“动作过小”之间反复震荡。

因此，下一阶段采用 Teacher-Student 分层混合架构：先用规则和状态机建立可解释的稳定跨越基线，再让 RL 在有限范围内微调，而不是让网络从零同时学习节律、地形理解、重心转移和安全恢复。

## 2. 总体架构

```text
传感器与本体状态
  ├─ LiDAR 点云 -> 局部高度图 / 最近台阶距离
  ├─ IMU -> 机身姿态、角速度
  ├─ 关节编码器 -> 关节角、关节速度
  └─ 足端接触与正运动学 -> 足端局部坐标、支撑状态
                │
                ▼
       地形评估与任务判定
       （距离、台阶高度、足端是否上台、机身是否越缘）
                │
                ▼
      Teacher：规则 FSM + 步态原语
      （Trot / 预抬腿 / Crawl / 重心转移 / 后腿跟随）
                │ 产生基础目标关节角与教师相位
                ▼
      Student：有界 PPO 残差微调
      target = teacher_action + residual_scale * student_action
                │
                ▼
    安全约束层（关节限位、动作限幅、支撑检查、跌倒回退）
                │
                ▼
          MuJoCo / 真机执行接口
```

核心原则：Teacher 负责“任务上该做什么”，Student 负责“在教师动作附近做多小的修正”，安全约束层有权覆盖前两者。

## 3. 感知与任务判定层

### 3.1 输入

- 当前 10×10 或后续更高分辨率局部高度图；
- 高度图估计的最近台阶水平距离；
- 四足相对机身中心的局部 3D 坐标；
- 四足接触状态；
- 机身高度、姿态四元数、线速度和角速度；
- 12 个关节角与关节速度。

当前 163 维环境已经包含上述大部分信息，应作为 Teacher 和 Student 共用的感知基础。后续如果要让网络显式知道 FSM 阶段，可在接口设计完成后增加少量 Teacher 相位/意图维，但这属于下一阶段的接口变更，本轮不修改。

### 3.2 输出

- 台阶前缘相对机身中心的水平距离；
- 台阶高度估计；
- 每只前足是否已接触台面；
- 每只后足是否已接触台面；
- 机身中心是否越过台阶前缘；
- 当前支撑足集合；
- 当前姿态、速度和关节是否处于安全范围。

### 3.3 判定原则

- 使用当前帧物理状态判定支撑、落足和登顶，不使用历史锁存状态替代真实接触；
- 台阶几何和高度图只用于局部相对判断，不依赖世界绝对坐标；
- 所有阈值都必须由基准实验标定，文档中的数值只是候选范围，不是未经测试的硬编码承诺；
- 当 LiDAR 数据缺失或高度图异常时，FSM 进入保守状态，不允许继续加速。

## 4. Teacher：规则 FSM 与步态原语

### 4.1 状态划分

以下是规划状态，不代表代码中已经存在：

| 状态 | 目的 | 主要行为 | 进入下一状态的条件 |
|---|---|---|---|
| `STAND_IDLE` | 初始稳定 | 站立、保持姿态、检查传感器 | 收到开始指令且传感器有效 |
| `TROT_APPROACH` | 平地接近 | 对角 Trot，向台阶方向前进 | 最近台阶距离进入预判区 |
| `PRELIFT_ASSESS` | 近台减速与预判 | 降速、保持直线、根据高度图选择抬腿时机 | 进入安全起跨区 |
| `CRAWL_ASCENT` | 近台慢速跨越 | 单腿摆动、至少三足支撑、高抬腿目标 | 前足稳定落台 |
| `WEIGHT_TRANSFER` | 重心前移 | 调整机身位置和支撑足目标，推动机身越缘 | 机身重心进入台面上方 |
| `REAR_FOLLOW` | 后腿跟随 | 逐条后腿抬起并落到台面 | 四足均有台面支撑 |
| `TOP_STABILIZE` | 顶部稳定 | 收腿、降低速度、检查姿态 | 稳定保持后完成任务 |
| `RECOVERY` | 失败恢复 | 停止、回退、重新对准或安全终止 | 恢复成功或达到重试上限 |
| `DONE` | 任务完成 | 保持稳定站立 | 人工复位或下一次任务 |

### 4.2 平地 Trot

Teacher 的第一层能力是稳定的平地移动，而不是直接把 PPO 当作步态发生器。

规划要求：

- 采用对角腿成对摆动的 Trot；
- 摆动腿和支撑腿交替明确；
- 全局速度由任务层给出，实际关节目标由步态原语生成；
- 落地接触用于校正相位，不能只依赖开环正弦；
- 机身姿态和关节限位处于安全范围时，才允许提高速度；
- 接近台阶前主动平滑减速，避免最后一刻急停。

Trot 原语只负责接近阶段。进入近台区域后，不再强调高速步态，而应切换到可控的 Crawl。

### 4.3 雷达预判与高抬腿

接近台阶时，使用局部高度图和最近台阶距离决定预抬腿时机：

1. 距离较远：保持 Trot，头部朝向台阶；
2. 进入预判区：降低线速度，稳定机身，估计台阶前缘；
3. 进入起跨区：选择前腿作为引导腿，提高摆动足净空；
4. 只有当前支撑满足安全条件时，才允许摆动腿离地；
5. 落足点应位于台面内部，而不是只搭在前缘。

所有高度和距离阈值都要在 0.025 m、0.035 m、0.04 m 等场景上分别标定，避免再次把某个低台阶参数当成通用参数。

### 4.4 近台 Crawl

Crawl 用于把“前腿搭台”转化为“整个机身和四足都上台”。规划行为链：

1. 前腿高抬并落到台面；
2. 保持至少三足支撑，禁止四足同时腾空；
3. 通过支撑足调整机身，使重心逐步越过台阶前缘；
4. 前足稳定后，依次抬起后腿，将后足落到台面；
5. 四足均获得台面支撑后，进入顶部稳定状态。

安全约束：

- 单腿摆动时至少三足支撑；
- 未检测到前足真实落台，不进入后腿跟随；
- 机身重心未越缘时，不允许只靠后腿踢动刷进度；
- 任一时刻检测到倾角、高度、关节限位或接触异常，立即退出 Crawl；
- Student 在状态切换和首次上台阶段暂时关闭或限制残差，避免网络破坏关键接触。

### 4.5 失败回退

FSM 需要区分可恢复失败和不可恢复失败：

- 可恢复：落足偏前、短暂打滑、速度过低、姿态轻微偏差。处理方式是停止摆动、回到稳定支撑、重新对准后有限次重试；
- 不可恢复：跌倒、关节越限、传感器失效、连续重试失败。处理方式是冻结动作、进入安全停机，并在仿真中按 episode 规则重置。

具体阈值、重试次数和回退距离必须通过基准实验确定，不能在没有测试数据时写成固定结论。

### 4.6 Teacher 基线验收

在进入 Student 阶段之前，Teacher 应至少通过以下门槛：

- 在固定 0.04 m 台阶场景中，20 个随机种子下完成四足登顶且过程无穿模；
- 不出现连续两步以上的四足全腾空；
- 不出现“前足搭台后长时间悬挂”；
- 终端能够打印每个 FSM 状态、接触足、台阶距离和终止原因；
- 相同配置重复运行时结果可复现；
- 即使失败，也能给出明确的失败状态，而不是无限超时。

如果 Teacher 无法稳定通过，不应通过增加 PPO 训练步数来掩盖问题。

## 5. Student：有界残差学习

### 5.1 动作接口

规划的关节目标合成公式：

```text
q_target = q_teacher + alpha * clip(a_student, -1.0, 1.0)
```

其中：

- `q_teacher`：Teacher FSM + 步态原语输出的 12 维目标关节角；
- `a_student`：PPO 的 12 维归一化残差动作；
- `alpha`：残差缩放系数，单位 rad；
- `clip`：逐维限幅，避免单步大动作；
- 最终目标还必须经过关节限位、速度限制和动作变化率检查。

`alpha` 不应直接沿用历史上 0.06、0.10、0.20 等值。它必须在 Teacher 基线稳定后，通过小幅动作扫描单独标定。

### 5.2 网络职责

Student 只学习：

- 对落脚时机的前后微调；
- 对机身姿态的小幅补偿；
- 对接触误差和轻微扰动的响应；
- 对地面摩擦、载荷和传感器噪声的鲁棒性。

Student 不负责：

- 从零发现 Trot 节律；
- 直接决定是否全腾空；
- 绕过 FSM 执行后腿跨越；
- 覆盖跌倒保护和关节限位；
- 用全局绝对坐标生成动作。

### 5.3 观测建议

第一版 Student 可以复用当前 163 维观测，以降低接口风险。后续若要显式利用 Teacher 信息，可增加：

- 当前 FSM 状态 one-hot 或阶段标量；
- Teacher 当前相位 sin/cos；
- Teacher 参考足端高度/关节目标残差；
- 最近台阶距离与置信度。

新增观测必须同步更新 `check_env()`、测试和文档，不能只改数组拼接而保留旧测试。

### 5.4 奖励设计原则

Student 的奖励应以“跟随稳定 Teacher + 完成当前阶段任务”为主，而不是重新奖励每一个容易作弊的子动作：

1. Teacher 动作跟踪误差；
2. 任务进度，例如机身相对台阶前缘的单调推进；
3. 四足支撑与接触合法性；
4. 机身姿态、高度和关节安全；
5. 动作平滑、动作变化率和能耗；
6. 成功跨越与跌倒终止。

应避免：

- 单独按抬脚高度持续给分；
- 长期存活即可积累大量奖励；
- 只按机身 X 位移给分而不检查接触；
- 在未真正落台时给“后足落台”奖励；
- 对绝对动作均值做强 L2 正则，导致网络失去发力能力。

### 5.5 安全盾

无论 PPO 输出什么，执行前都要经过：

- 动作范围裁剪；
- 关节位置和速度限制；
- 动作变化率限制；
- 支撑足合法性检查；
- 机身倾角、高度和接触异常检查；
- 关键状态切换时自动回退到纯 Teacher 动作；
- 连续异常时安全停机。

安全盾不是奖励函数的一部分，而是运行时硬约束。

## 6. 分阶段实施路线

### 阶段 A：Teacher 基线（下一步唯一主线）

交付物：

- 纯代码 FSM 与步态原语；
- 固定地形下的可重复跨台阶演示；
- 终端状态日志和失败原因；
- 20 种子评测脚本；
- 不涉及 RL 训练。

完成标准：在 0.04 m 单级台阶上稳定完成完整行为链，且失败可解释。

### 阶段 B：Teacher 数据与接口冻结

交付物：

- 记录 Teacher 状态、动作目标、接触和地形观测；
- 确定 Student 的观测、动作和奖励契约；
- 建立 Teacher 回放和单元测试；
- 确认残差缩放与安全盾参数范围。

完成标准：同一份数据可以稳定复现 Teacher 动作，Student 接口通过 `check_env()`。

### 阶段 C：Student 残差预训练

先在平地或低台阶上训练残差，目标不是重新学习步态，而是：

- 减小跟踪误差；
- 提升抗扰动能力；
- 保持接触合法性；
- 不降低 Teacher 成功率。

完成标准：Student 在多个随机种子下不劣于 Teacher，并能在扰动条件下减少失败。

### 阶段 D：台阶微调与域随机化

逐步增加：

- 台阶高度扰动；
- 台阶前缘位置扰动；
- 摩擦和负载扰动；
- 传感器噪声和短时丢帧；
- 起始姿态和初始速度扰动。

每次只增加一个变量，并保留 Teacher 对照实验。

### 阶段 E：多级楼梯

只有在单级台阶 Teacher 和 Student 均稳定后，才扩展为多级楼梯。届时需要新增：

- 楼梯级数和级高估计；
- 连续前缘检测；
- 每级台阶的局部落脚点规划；
- 上楼、平台和下楼的安全状态；
- 更严格的能耗、速度和姿态约束。

## 7. 评测规范

所有阶段统一记录：

- 成功率；
- 平均前进距离；
- 平均回合长度；
- 四足全腾空时间比例；
- 前后足落台次数；
- 悬挂/死区终止次数；
- 平均绝对动作与动作饱和率；
- 最大/平均机身倾角；
- 关节越限和物理穿模次数；
- Teacher/Student 动作差；
- 失败状态分布。

评测必须同时报告固定种子结果和多个随机种子结果。只展示最佳回放不能作为验收。

## 8. 关键风险与待确认项

1. **台阶高度与 LiDAR 分辨率匹配**：4 cm 台阶需要足够的垂直分辨率，否则 FSM 可能把台面误判为平地；
2. **接触判定延迟**：仿真接触和真实足端开关存在差异，Teacher 不能只依赖单帧接触；
3. **Crawl 速度**：速度过慢可能被死区逻辑误判，速度过快会增加前腿撞台风险；
4. **残差缩放**：过大破坏 Teacher，过小无法提升鲁棒性；
5. **状态切换抖动**：需要滞回和最小驻留时间，不能用瞬时阈值反复切换；
6. **多级楼梯泛化**：单级台阶的固定阈值不能直接复用于连续台阶；
7. **安全回退**：回退动作本身必须经过碰撞和关节限位检查。

以上参数都需要在后续实现阶段通过基准测试确认，本文不做无依据的数值承诺。

## 10. 下一轮启动条件

只有在以下条件满足后才进入代码实现：

1. 确认采用本 Teacher-Student 路线；
2. 确定 Teacher 第一阶段只做 0.04 m 单级台阶；
3. 明确允许修改的文件范围；
4. 先实现 Teacher 和可重复评测，不直接启动 RL 长训；
5. 逐阶段验收，任何阶段失败都回到上一阶段修正，而不是用训练步数掩盖问题。
