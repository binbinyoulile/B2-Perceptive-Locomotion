# AS2 爬梯实测：后腿能不能收上来

> 场景：0.195 m 高 / 0.18 m 深钢梯（`simulations/mujoco/as2_stairs_static/scene.xml`）。
> 控制器：50 Hz PD，`τ = kp(target−q) − kd·q̇ + qfrc_bias`，kp/kd = 400/12（平地标定值），
> 动作由人手写的 FSM 序列给出（每拍先挪重心、再抬一只脚）。**没有任何训练**。
> 复现：`D:\Python313\python.exe .\experiments\as2\as2_stair_gait.py`

## 1. 结论（先看这一页）

| 问题 | 实测答案 |
| --- | --- |
| 跨级站姿（前足二级、后足一级）站得住吗 | **站得住**。2.5 s 峰峰 0.09 mm、足端滑移 0.07 mm |
| 第一条后腿（右后）能不能收到二级 | **能**。重心先前移 4.5 cm（余量 +2.1 cm）后抬脚，落点误差 3.2 cm，机身 z 0.565 m、横滚 0.9° |
| 第二条后腿（左后）能不能收到二级 | **不能**。抬脚前重心余量只剩 **+0.4 cm**，抬脚 0.1 s 内俯仰 −36°，1.5 s 内横滚 152° 翻倒 |
| 纯规则（FSM）能爬完一级吗 | **不能**，卡在第 2 步（共 8 步：收两条后腿 → 前移 → 上三级 → 后腿跟进） |
| 修正支撑深度口径（0.124 → 0.18 m）有帮助吗 | **没有**。抬腿那一刻的约束是"三足支撑三角形"，不是踏面有多深 |

一句话：**AS2 能把一条后腿收上来，第二条收不上来。**
卡点不是踏面深度，也不是腿长，而是"第二条后腿"那一步的三足支撑三角形只有
**4 mm** 的重心余量——抬腿的惯性就把这点余量吃掉了。

## 2. 逐步数据（每一步都是实测）

| 步骤 | 抬脚前重心余量 | 结果 |
| --- | --- | --- |
| 起手跨级站姿 | — | 稳定，机身 z 0.556 m，4 足接触 |
| 挪重心（前移 4.5 cm） | — | x 0.390，z 0.566，横滚 0.0° |
| 1 右后腿上二级 | **+2.1 cm** | **成功**，z 0.565、横滚 0.9°、落点误差 32 mm |
| 落稳 | — | z 0.567、横滚 0.2° |
| 挪重心（再前移） | — | x 0.457、z 0.566 |
| 2 左后腿上二级 | **+0.4 cm** | **翻倒**：0.1 s 俯仰 −36°，1.5 s 横滚 152° |

注意第 2 步的余量：抬第一条后腿时有 2.1 cm，抬第二条时只剩 0.4 cm。
原因很直接——第一条后腿落上二级后，支撑三角形从「前二后二」变成
「两只前足 FL/FR + 一只右后足 RR」，而重心必须落在**左前到右后的那条斜边**以内；
每抬一只后腿，重心都要再往前压一点，但机身前移的空间被前腿可达范围卡死（前腿已伸展 58%→更直）。

## 3. 为什么"修正支撑深度"没帮上忙

- 踏面可用深度只影响"四足同踩一级"时脚能摆多开（0.124 m 保守口径 / 0.18 m 物理口径）。
- 而这次失败发生在**三足支撑**阶段：总有一只脚在腾空，约束变成"重心投影必须在另三足的三角形内"。
  三角形由三只已落地的脚决定，和踏面还空着多深无关。
- 所以把口径从 0.124 改到 0.18，抬腿这一步的余量不会变（仍是 0.4 cm 量级）。

## 4. 还差什么（下一步的可选项）

1. **横移重心**：现在这条 FSM 只能前后挪（机身 y 固定 0.468）。抬左后腿时重心应该往右下压，
   这需要髋 roll 参与 + 三维 IK。这是最直接的一步，预计能把第 2 步撑过去。
2. **降低抬腿速度/高度**：现在 1.5 s 抬 16 cm；慢一点、低一点能减少冲量（但会拉长单腿支撑时间）。
3. **允许腾空**：对角小跑（trot）时两足同时离地，机器人靠动量过级，不受三足三角形约束——
   这也是真机爬梯的常见做法，但需要训练或 MPC，不是手写序列能覆盖的。

## 6. 已知限制

- 这是**手写动作序列**，失败只说明"这条序列不行"，不能证明"AS2 一定爬不上去"；
  第 4 节第 1 条（横移重心）还没试。
- 没有做腾空相、没有做 MPC/RL；PD 增益只在本场景标定。
- "重心余量"是重心投影到三足三角形最近边的垂直距离；实际还有滚动/俯仰的动力学余量问题，
  实测在 +0.4 cm 时 0.1 s 内就翻，说明工程上至少需要 1.5–2 cm 才够抬脚。
