# B2 在 0.195 m / 0.18 m 窄踏面钢梯上的步态探索

> 时间：2026-11-06
> 问题：45° 钢梯（每级升 0.1853 m、进 0.1853 m），踏面只有 0.18 m 深。B2 该用什么步态？
> 结论先说：**换了几种策略，没有一种能爬上去**；但失败点很明确，不是"没调好"，
> 而是几何+重心窗口的硬约束。下面每个数字都是 MuJoCo 实测。
> 复现：`D:\Python313\python.exe .\experiments\b2\b2_stair_gait.py`
> 观看：`D:\Python313\python.exe .\experiments\b2\b2_gait_view.py`

---

## 1. 先算死结：为什么"前足高一阶、后足低一阶"是唯一姿态

| 量 | 值 |
|---|---|
| 髋距 | 0.657 m |
| 单腿最大伸展 | 0.700 m |
| 踏面深 | 0.180 m |
| 每级升/进 | 0.1853 m |
| 支撑深度（四足同踩一级） | 0.180 − 2×0.032 = **0.116 m** |
| 同踩时重心余量上界 | 0.058 − 0.021 = **3.7 cm** |

若**前足比后足高两级**（差 0.371 m），后腿要跨 `0.371 + 0.55 ≈ 0.92 m > 0.70 m` → 不可能。
所以每时每刻只能是"前足高一阶、后足低一阶"。而后足要追上来，就必须先落到前足脚下
那一级 → **"四足同踩一级"这个姿态不可避免**，每爬一级都要经过它一次。

这就是这一题真正的瓶颈，不是步态形式。

---

## 2. 试了什么（脚本化动作序列 + PD 跟踪，kp 800/kd 20 + 重力前馈）

所有动作都是"世界坐标足位 + 机身位姿 → 逆解 12 个关节角 → PD 跟踪"，不是硬摆 qpos。

### A. 四足同踩一级，静态保持 2.5 s

| 结果 | 值 |
|---|---|
| 机身 z | 0.5114 m（相对投放 0.50 反而抬了 1.1 cm） |
| 最大倾角 | 5.3° |
| 是否跌落 | **没有** |

**这个瓶颈姿态本身是稳的。** 说明"站上去"不是问题，问题在后面。

### B. 从同踩姿态单独抬左前足到上一级（3 足支撑）

| 结果 | 值 |
|---|---|
| 前进 / 上升 | **−0.008 m / +0.013 m**（等于没动） |
| 最大倾角 | 5.3°（没翻） |
| 左前小腿高度 | 0.698 m（抬起来了，但只到 0.35 左右，目标踏面 0.412） |
| 其余三足 | FR 0.572 / RL 0.230 / RR 0.229（都还在原位） |

抬得起来，但**机身不跟着走**。

### C. 四拍爬行：每拍先挪重心到其余三足形心，再抬一只脚上一级（FL→RR→FR→RL）

| 结果 | 值 |
|---|---|
| 前进 / 上升 | **−0.025 m / +0.012 m**（甚至被推回去一点） |
| 最大倾角 | 5.3° |
| 四足末态 | 前两只抬着、后两只没动 |

依旧推不动。**四拍全跑完，机身位移是负的。**

### D. 为什么："抬前足"这个动作本身就把重心甩出支撑面

四足同踩一级时，重心投影在 (0.328, 0.468)，四足全落时在支撑多边形内。但只要抬一只：

| 抬起 | 重心是否还在支撑三角形内 | 到最近边距离 |
|---|---|---|
| **FL** | **否（跑到外面）** | −30.4 mm |
| **FR** | **否** | −30.4 mm |
| RL | 是 | +22.2 mm |
| RR | 是 | +22.2 mm |

也就是说：**这个站姿下前足根本不能单独抬**——一抬重心就在支撑面外 3 cm，机器人会朝对角翻。
要抬前足，必须先把重心往后挪 ≥ 3 cm（加上安全余量约 4 cm）；而 0.116 m 的支撑面
一共只给 ±3.7 cm 的余量，挪完只剩 **不到 1.5 cm** 留给控制误差。

B、C 两轮实测里，PD 的跟踪误差本身就有 1~3 cm（抬脚时前腿的关节误差把机身往回推），
正好把这点余量吃掉——所以看到的现象是"脚抬起来了、机身没动、整体还被推回去一点"。

## 3. 结论：最佳策略与成功率

**最佳策略 = "四足同踩一级 + 每拍先挪重心再抬脚"的四拍爬行。**
它是唯一在几何上成立的序列（A 证明站得住、D 证明只需 4 cm 的重心预置）。

**成功率：0/3 个循环，0 级台阶。** 走完全部四拍，机身前进了 −2.5 cm。

**核心物理阻碍（按重要性）：**

1. **踏面 0.18 m < 髋距 0.657 m 的 1/3**。四只脚同踩一级时，支撑面只有 0.116 m 深，
   重心窗口 ±3.7 cm；抬前足还要再往外 3 cm。**每拍都要在 1.5 cm 的窗口里完成 0.185 m 的
   抬脚 + 0.185 m 的机身推进**——这已经不是"步态调参"能解决的事。
2. **每级 0.185 m 的抬升 = 腿行程的 26%**，而且必须在重心压在另三只脚的时候完成。
   静态爬行的时间常数被 PD 的跟踪误差锁死：动得太快就甩出支撑面，动得太慢就被误差推回去。
3. **推重比不是瓶颈**（calf 320 N·m / 0.35 m → 单腿 914 N，四腿 3657 N 对 677 N 体重），
   所以"加大力矩"救不了；**行程与支撑面才是瓶颈**。

## 4. 如果一定要爬这个楼梯，按可行性排序

1. **改环境**：踏面 ≥0.25 m 或台阶 ≤0.15 m。这一条直接把窗口从 1.5 cm 拉到 6 cm 以上，
   四拍爬行立刻变成"调参问题"。
2. **训练动态步态**（Isaac Lab + 域随机化），而不是手写序列。动态策略可以借用惯性
   跳过"四足同踩"这个静态瓶颈，但需要 10⁷ 量级的样本与真机标定，且成功率不会高。
3. **换狗**：髋距更窄、腿行程更长的机型（髋距/踏面 比值越小越有利）。B2 的 0.657/0.18 = 3.65，
   这个比值直接决定"四足同踩"是否可行。
4. **跳跃式**：理论上可以从前一站姿直接越到下一级，但需要 0.37 m 的垂直起跳与精确落点，
   以 B2 的推重比和足端橡胶摩擦（μ≈0.9）来看，落点误差 >5 cm 就会翻，不建议作为首个方案。
