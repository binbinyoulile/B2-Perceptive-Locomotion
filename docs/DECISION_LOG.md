# 技术决策记录

## D001：以 MuJoCo 作为第一阶段主仿真器

日期：2026-10-25

决定：

- 第一阶段使用 MuJoCo Python API 和 MJCF。
- IsaacLab、PyBullet 等暂不作为主环境。

理由：

- 当前已有可运行的 Go2 MJCF 和楼梯场景；
- MuJoCo 接触、执行器和 Python API 适合快速实验；
- 后续仍可通过 MJX 做 GPU 批量训练。

## D002：官方模型与实验场景分离

决定：

- 官方模型放在 `models/unitree_go2/`；
- 可运行实验场景放在 `simulations/`；
- 不在官方模型目录中直接做大量实验性修改。

理由：

- 保持来源清晰；
- 场景升级时仍能追溯原始模型。

## D003：楼梯显示网格与碰撞几何分离

状态：已确定，待实施。

决定：

- STL 仅作为视觉网格；
- 后续按踏步和平台建立简化碰撞体；
- 不对整个楼梯网格直接启用碰撞。

理由：

- 凹形网格的凸包近似会填平阶梯；
- 简化碰撞体更稳定、更快，也便于参数化课程学习。

## D004：强化学习先平地后楼梯

决定：

- 先完成平地站立、步态和训练闭环；
- 再通过台阶课程逐步引入复杂地形。

理由：

- 降低探索和奖励设计难度；
- 可区分环境错误、控制器问题和算法问题；
- 更容易形成可复现基线。

## D005：外部代码只作为参考

决定：

- `go2_gait_planner` 放在 `control/upstream/`；
- 不直接把它当作项目主代码；
- 许可证明确前不复制其核心实现。

理由：

- 本地工程许可证未确定；
- 其依赖 ROS2 Foxy 和 Unitree ROS2，与当前纯 Python MuJoCo 基线不完全一致。

## D006：项目内 MuJoCo 脚本使用相对路径

日期：2026-10-25

决定：

- 运行前 `os.chdir(脚本目录)`；
- `from_xml_path("scene.xml")` 使用相对路径。

理由：

- 当前 MuJoCo Windows 构建直接打开中文绝对路径会失败；
- 相对路径方式已经过实测。

## D007：IsaacLab/RL 工程作为独立上游参考

日期：2026-10-25

决定：

- `go2_omniverse` 完整快照放在 `reinforcement_learning/upstream/go2_omniverse/`；
- 不将 Isaac Sim、IsaacLab 或 ROS2 引入当前 MuJoCo 第一阶段环境；
- 只参考其环境组织、地形课程和奖励设计，再自行实现适合本项目的代码。

理由：

- 当前 Windows 环境已有可运行的 MuJoCo 基线；
- IsaacLab 栈依赖 Linux、ROS2 和较大的 GPU/软件环境，接入成本高；
- 保持当前项目可快速复现，避免同时维护两套仿真栈。

## D008：楼梯尺寸先使用 STL 估计值

日期：2026-10-25

决定：

- 在拿到正式 CAD 尺寸前，使用 `models/stairs/geometry_estimate.json` 作为碰撞体原型输入；
- 所有实验配置标注“STL 估计尺寸”；
- 正式的上下楼对照实验前，再用图纸或实测确认尺寸。

理由：

- 当前 STL 已能稳定提取 7 个可落脚面；
- 先建立可运行的碰撞体原型有利于尽早发现环境和控制问题；
- 保留尺寸来源标记，避免把估计值误当成最终设计值。
