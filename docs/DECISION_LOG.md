# 技术决策记录

## D001：以 MuJoCo 作为第一阶段主仿真器

日期：2026-10-25

决定：

- 第一阶段使用 MuJoCo Python API 和 MJCF。
- IsaacLab、PyBullet 等暂不作为主环境。

理由：

- 当前已有可运行的 Go2 MJCF 和楼梯场景；
- MuJoCo 接触、执行器和 Python API 适合快速实验；
- 后续仍可通过 MJX 做 GPU 批量训练。

## D002：官方模型与实验场景分离

决定：

- 官方模型放在 `models/unitree_go2/`；
- 可运行实验场景放在 `simulations/`；
- 不在官方模型目录中直接做大量实验性修改。

理由：

- 保持来源清晰；
- 场景升级时仍能追溯原始模型。

## D003：楼梯显示网格与碰撞几何分离

状态：已实施并扩展（49 个分类 box 碰撞体）。

决定：

- STL 仅作为视觉网格；
- 7 个落脚面各用 20 mm 薄板 box，板下保持镂空；
- 另建立立柱、侧梁、横撑和栏杆的简化碰撞；
- 不对整个楼梯网格直接启用碰撞。

理由：

- 凹形网格的凸包近似会填平阶梯；
- 简化碰撞体更稳定、更快，也便于参数化课程学习。

## D004：强化学习先平地后楼梯

决定：

- 先完成平地站立、步态和训练闭环；
- 再通过台阶课程逐步引入复杂地形。

理由：

- 降低探索和奖励设计难度；
- 可区分环境错误、控制器问题和算法问题；
- 更容易形成可复现基线。

## D005：外部步态参考快照已移除

决定：

- 不再在项目内保存 `go2_gait_planner` 源码快照；
- 其思路只保留为学习和架构参考，不进入当前运行链路；
- 若后续需要复用代码，先确认许可证和当前 ROS2 版本兼容性。

理由：

- 本地工程许可证未确定；
- 其依赖 ROS2 Foxy 和 Unitree ROS2，与当前纯 Python MuJoCo 基线不一致；
- 保留完整快照会增加检索成本和仓库体积，当前阶段不需要。

## D006：项目内 MuJoCo 脚本使用相对路径

日期：2026-10-25

决定：

- 运行前 `os.chdir(脚本目录)`；
- `from_xml_path("scene.xml")` 使用相对路径。

理由：

- 当前 MuJoCo Windows 构建直接打开中文绝对路径会失败；
- 相对路径方式已经过实测。

## D007：IsaacLab/RL 外部快照不作为当前依赖

日期：2026-10-25

决定：

- 移除 `go2_omniverse` 完整源码和训练检查点快照；
- 不将 Isaac Sim、IsaacLab 或 ROS2 引入当前 MuJoCo 第一阶段环境；
- 后续 Gymnasium 环境和训练代码全部以本项目需求独立实现。

理由：

- 当前 Windows 环境已有可运行的 MuJoCo 基线；
- IsaacLab 栈依赖 Linux、ROS2 和较大的 GPU/软件环境，接入成本高；
- 避免同时维护两套仿真栈，并让仓库只保留当前可运行、可审计的资产。

## D008：以 STL 作为当前楼梯几何来源

日期：2026-10-25

决定：

- 当前直接使用 `models/stairs/steel_stair.STL` 解析并构建几何与碰撞，不再把 STL 尺寸列为待确认事项；
- `models/stairs/geometry_estimate.json` 由解析脚本重建，保留源文件 SHA-256 和坐标变换；
- 若后续出现新版 CAD 或实测模型，按新输入重新生成并执行完整回归。

理由：

- 当前 STL 已能稳定提取 7 个可落脚面；
- 固定几何来源可让碰撞、路线和后续实验共享同一坐标基准；
- 原始 STL 保持不变，派生结果可以重复生成和审计。
